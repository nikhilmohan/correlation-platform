# MVP Achievability / Go-No-Go Assessment — AI/ML Alarm Correlation Platform (Core IP)

**Final design gate before the phase-by-phase build.** This assessment is evidence-grounded in the *hardened* (readiness-fixes / alignment) designs on the per-service branches and `origin/main` docs, and adversarially re-verified target-by-target against the actual design text — not against intent. Verdicts below are reproduced faithfully from the verified analysis; none have been upgraded. The question this gate answers: *can the design, as written, accurately and evidently demonstrate the MVP targets?*

The headline: the **mechanisms are sound and the measurement plumbing is real**; the residual exposure is concentrated in **grounded magnitudes** (alarm volume, distinct-pattern count, per-pattern length) that today rest on unstated tuning or an under-sized Core IP pack, plus a handful of **un-asserted headline rates** (auto-handled %, auto-correlation %) that are *shown* but not *gated*.

## GO / NO-GO Summary

**Overall verdict: ⚠️ CONDITIONAL GO — proceed to build, with a short, mandatory pre-build decision list.**

**Verdict counts (24 targets, faithful to the verified analysis):**

| Verdict | Count | Targets |
|---|---|---|
| ✅ Achievable | 14 | Multi-layer topology; configurable size; grounded attributes; topology upload; codebook generation; web-ui P1 elements; ≥3 noise classes; Pattern Manager RCA/lifecycle; ground-truth labels/oracle; live replay; ~60% measurable+shown; matching mechanisms; domain extensibility; cross-domain structure |
| ⚠️ At-risk | 8 | ~10 grounded sites (demo profile); Knowledge pack drives trails (`igpArea`); Trail Builder area-bounding; ~1000 alarms; ~55% coverage; 75-80% auto-handled; DBSCAN removal/retention on hard-noise corpus; PrefixSpan quality ≥0.80; ~500 live; ~60% correlation capability; reuse-on-noisy-stream; demonstrability richness *(note: P3/roadmap rows shared)* |
| ❌ Gap | 2 | **8-10 patterns × 10-20 alarm TYPES** (P2 — magnitude, not tuning); **~60% auto-correlation rate asserted/gated** (P3 — no metric/oracle exists) |

> *Counts above reflect every distinct row in the four phase tables; some at-risk concerns recur across phases (volume, pack size) and are listed once per appearance.*

**Headline:** The architecture, contracts, mechanisms, and the entire *measurement* layer (ground-truth labels, integration-threshold metrics, stats APIs, web-ui surfaces) are sound and Achievable — **the build can start.** No re-architecture is required for any finding. The residual risk is almost entirely **grounded magnitude + assertion plumbing**, fixable by data authoring, config pinning, and a few added integration-threshold metrics — not by structural change.

**Must-decide BEFORE / AT the start of build (gate conditions):**

1. **P2 pattern magnitude (❌ Gap — requires a human decision).** Either **(A) extend the Core IP pack** — author ~6 more scenario types and lengthen `alarmTypeVocabulary` + propagation templates so cascades reach 10-20 distinct types (a **contract change → `docs/architecture.md` + human approval**), or **(B) re-baseline the MVP target** to "4 patterns of ~5-7 types," which the current design demonstrates exactly. *This is the single most consequential decision and cannot be closed by tuning.*
2. **Fix the `igpArea` inconsistency (P1 — blocks two At-risk targets).** Either emit a grounded `igpArea` per Node/Interface and add it to `attributeCatalogue` (recommended), or set `trailPolicy boundary:{type:'none'}` and document area-bounding as deferred. Add an integration assertion on Simulator data, not igpArea-injected fixtures.
3. **Pin reproducible demo profiles** (P1 SITE_COUNT=10/larger node count; P2 ~1000-alarm config; P3 ~500-alarm config) as checked-in presets, and **assert the volumes** via `simulator_alarms_emitted_total` in `integration-thresholds.yaml`.
4. **Add the two missing headline-rate metrics** — `autoHandledFraction` (P2) and `correlatedFraction`/`autoCorrelationRate` (P3) — to `integration-thresholds.yaml` and the test oracle, computed from the same APIs the demo shows, so the *demoed number equals the asserted number*.
5. **Calibrate + check in DBSCAN eps/min_samples** (and minSupport, partialMatchTolerance) in Knowledge model-params for the default corpus, and assert removal ≥0.90 AND retention ≥0.95 on a **full** P2 run (not just synthetic windows), plus a P3 seeded-cascade-plus-noise correlation test.
6. **(Lower priority)** Add an offline-evaluated RCA-accuracy tile to the dashboard so the strongest "power" metric is visible to the operator, not only in the integration report.

If decision (1) and fixes (2)-(5) are accepted into the build plan as gated tasks, **GO.** The platform's design is structurally complete; what remains is grounded-data sizing and turning *shown* numbers into *gated* numbers.

## Confirmed Capabilities (what makes the demonstration numbers reachable)

These are the concrete, verified design features the assessment relies on — the foundation that justifies a GO:

- **Simulator config knobs** — `SITE_COUNT` (1..node-count), `TOPOLOGY_NODE_COUNT` (10-200), `INTERFACES_PER_PORT` (1-8), `SCENARIO_INSTANCES` (5-10), `NOISE_RATE` (0.2 default, [0,1]), `NOISE_MIX` (4 named classes), `BACKGROUND_FRACTION`, `HARD_NOISE_FRACTION` (0.4), `PACING_MULTIPLIER`, deterministic `SIM_SEED` — every demonstration knob is settable and fail-fast validated. *(The known gap: there is no single TOTAL_ALARMS knob — volume is emergent and must be pinned via a profile.)*
- **Grounded Core IP domain pack** — 11 object types, 9 edge relations, 8 alarm tokens, fault-origin types, full propagation-template chain, trail policy, attribute catalogue — all seeded idempotently through Knowledge's validated write path and mutually aligned with the Simulator's well-known keys. *(Gap: only 4 scenarios and a 6-deep max cascade — the magnitude shortfall.)*
- **Knowledge-sourced ML parameters** — DBSCAN `eps`/`min_samples`, PrefixSpan `minSupport`/`maxPatternLength`/adaptive-window, CE `partialMatchTolerance` and conflict weights are all read from Knowledge model-params (no hard-coded thresholds), so the demonstration can be tuned without code change. *(Action: calibrate + pin them for the default corpus.)*
- **Ground-truth label oracle** — per-scenario `GroundTruthLabel` (`rootCause`, `rootCauseManagedObjectId`, `rootCauseAlarmType`, `children[]`) to `labels-<runId>.jsonl` + frozen `/labels`; noise identifiable by label-absence; per-class noise/background tagging — this is what makes removal, retention, pattern-quality, and RCA accuracy *computable* rather than asserted by hand.
- **Integration-threshold metrics that MEASURE the rates** — config-driven (`integration-thresholds.yaml`, AC 20), currently gating RCA accuracy ≥0.80, alarm-reduction ≥5×, noise removal ≥0.90, retention ≥0.95, pattern-quality ≥0.80. *(Action: add `autoHandledFraction` and `correlatedFraction` so the two headline percentages are gated, not just inferred.)*
- **Stats + query APIs that SHOW the numbers** — CE `GET /stats` (alarms processed, incidents created, pattern/codebook match counts, confidence distribution), Alarm Manager `GET /alarms?state=correlated` (canonical envelope), Topology `GET /topology/sites` + `/sites/{id}/objects` + `/traversal`, plus the full web-ui surface (geo map, site drill-down, trail overlays, `PatternXaiDetailComponent`, StreamingView, IncidentDetail, DashboardStore `alarmReductionRatio`) — the demonstration's evidence layer is built and frozen against producer contracts.
- **Data-driven extensibility** — `recordType` as data, domain-scoped generic controllers, generic `managedObjectId`, a domain-agnostic Simulator engine with a swappable DomainPack, and first-class opt-in cross-domain traversal — confirming the MVP can extend to new and cross-domain correlation **without re-architecture**, which de-risks the entire roadmap leg of the gate.
